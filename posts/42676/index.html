如何使用Github-Pages和Hexo搭建个人Blog

发表于 2022-03-29 更新于 2025-04-10

第一篇blog写自己如何搭建blog :D 边搭边写，所以可能有点混乱

需求

  • GitHub账号
  • Git
  • Node.js
  • Hexo

本文使用 Arch Linux + Hexo + GitHub Pages 部署

安装

首先是Git

然后是Node.js 我使用了fnm管理node环境 可通过AUR安装

安装好后，根据当前使用的shell配置环境
例如，如果使用的是fish则在 ~/.config/fish/conf.d/fnm.fish 中添加 fnm env --use-on-cd --shell fish | source
如果使用的是bash则在 .bashrc 中添加 eval "$(fnm env --use-on-cd --shell bash)"
其余shell可自行查看GitHub

设置好了后使用fnm安装Node.js 截止当前，最新的LTS版本是v22.14.0，而最新的版本是v23.11.0，选择喜欢的版本即可

也可以通过Arch官方仓库提供的版本

主题

主题可以在 https://hexo.io/themes/ 中找到(当然也能百度)

本文使用Next示范(我的blog可能不会使用这个主题)

有两种方法 使用npm安装和使用git安装

  • 使用npm
  • 使用git

这里我使用git进行安装

接下来需要在 _config.yml 中修改一些配置来启用主题

配置

Hexo 的配置请参考 https://hexo.io/zh-cn/docs/configuration

如果想配置Next的话，最好在站点根目录下创建新的配置文件而不是使用theme/next/_config.yml，否则会导致更新主题时冲突

Next 的官方文档位于 https://theme-next.js.org/docs

Next 支持多种评论服务 如 Disqus Gitalk Utterances 等 可按照官方文档进行配置 https://theme-next.js.org/docs/third-party-services/comments

写作

$ hexo new [layout] <title>

此命令会生成一篇布局为layout(如未指定则默认为post，当然可以在_config.yml里调)，标题为title的Markdown文件

在 _config.yml 开启 post_asset_folder 后 每次创建新post时都会自动生成同名文件夹 可以将各种post需要的资源放入其中
但是 据https://hexo.io/zh-cn/docs/asset-folders.html中所说 使用常规markdown语法和相对路径引用图片之类的资源会无法正常显示 需要通过标签插件引用

也可通过 hexo-renderer-marked 将markdown语法的图片解析为其对应文章的路径

部署

终于写到这里了，在之前的需求中提到了GitHub账号和Git，现在是用到这些东西的时候了

Hexo配置文件中和部署相关的部分是deploy，一开始的情况是这样

至少要有一个type参数，比如

当然type参数可以不止一个

不过由于这次使用的是GitHub Pages，所以只考虑Git

首先打开GitHub并创建一个仓库，仓库名必须是 <你的用户名>.github.io

然后修改_config.yml

接着安装hexo-deployer-git

之后进行Git账户设置，设置过的可以跳过这部分

在~/.ssh中有id_ed25519和id_ed25519.pub，复制id_ed25519.pub里面的所有内容

回到GitHub，选择 “Settings” -> “SSH and GPG keys” -> “New SSH key”，取个标题，将你复制的所有内容丢进Key里面，然后单击 “Add SSH key”

最后部署到你的GitHub仓库

然后在仓库的 Settings -> Code and automation -> Pages -> branch 中选择 master 并保存

大功告成！现在可以在https://<你的用户名>.github.io访问新博客了
